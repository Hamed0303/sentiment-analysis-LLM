# Reliable Compound AI for Social-Media Sentiment Decisions

Code, data, and per-tweet predictions for the paper:

> **Reliable Compound AI for Social-Media Sentiment Decisions: When Weighted Voting Outperforms Agentic Routing and Retrieval**
> Hamed Abdul Baseer, G. G. Md Nawaz Ali, Abdul Moid Khan Mohammed
> Department of Computer Science and Information Systems, Bradley University
> *Manuscript under review.*

We fine-tune three classifiers (Twitter-RoBERTa, RoBERTa-Large, `gpt-4.1-mini`) for three-class tweet sentiment, then compare seven ways of combining them: confidence-weighted voting (three weighting schemes), always-on RAG over two knowledge bases, and a LangGraph supervisor multi-agent system with and without capability hints. All systems are scored on the same 200-tweet held-out test set.

**Main finding:** a fixed, identity-weighted vote that puts most of the weight on the strongest model (0.60 / 0.20 / 0.20) is the best system. Per-tweet confidence routing, LLM orchestration, and retrieval all do worse.

## Repository layout

```
data/
  tweets_labeled.csv          999 manually labelled tweets (-1 / 0 / 1)
  train.csv, test.csv         stratified 80/20 split (799 / 200), random_state=42
  gpt_finetune_train.jsonl    chat-format training file used for gpt-4.1-mini
knowledge_bases/
  kb_a/                       KB A: hand-authored guideline PDF and its generator
  kb_b/                       KB B: five corpus-derived PDFs and their generator
src/
  split_dataset.py            regenerates data/train.csv and data/test.csv
  finetuning/                 Twitter-RoBERTa and RoBERTa-Large (Colab), gpt-4.1-mini (OpenAI API)
  voting/                     static-tier, static top-heavy, dynamic confidence-ranked voting
  rag/                        RAG over KB A and KB B
  multi_agent/                LangGraph supervisor, with and without capability hints
  analysis/                   evaluate.py (tables + significance) and figure scripts
results/predictions/          per-tweet predictions for every system in the paper
figures/                      figures used in the manuscript
```

## Setup

```bash
git clone https://github.com/Hamed0303/sentiment-analysis-LLM.git
cd sentiment-analysis-LLM
pip install -r requirements.txt
cp .env.example .env    # then fill in your keys
```

Run every command from the repository root.

**Reproduce the tables without any API keys:**

```bash
python src/analysis/evaluate.py
```

**Re-run a pipeline** (needs `OPENAI_API_KEY`, your fine-tuned `gpt-4.1-mini` ID in `FINETUNED_MODEL_HF`, and `HF_TOKEN`):

```bash
python src/voting/static_top_heavy_voting.py
```

The fine-tuned encoders are loaded from the Hugging Face Hub (`Hamed0303/twitter-roberta-hf-finetuned`, `Hamed0303/roberta-large-hf-finetuned`). The fine-tuned `gpt-4.1-mini` lives in the authors' OpenAI account and cannot be shared, so to re-run anything that calls it you need to fine-tune your own copy with `src/finetuning/finetune_gpt41_mini.py`. Because the API model is not deterministic across snapshots, re-run numbers may differ slightly from the saved predictions.

The encoder fine-tuning scripts are written for Google Colab: upload `data/train.csv` and `data/test.csv` and add `HF_TOKEN` under Colab Secrets.

## Data

The 999 tweets were collected from the Internet Archive (archive.org) and labelled by hand as negative (-1), neutral (0), or positive (+1): 443 positive, 320 negative, 236 neutral. No text normalisation was applied.

KB B was built from a separate, related corpus of 3,895 labelled social-media captions. That corpus is not included here; the generated KB B PDFs are.
